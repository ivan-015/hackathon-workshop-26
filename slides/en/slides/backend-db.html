Build the database

# connect the Supabase MCP to a dev project, then:

Create a jobs table (photo_url, part, manual_page, note,

user_id). Turn on RLS so users only see their own rows.

Add a storage bucket for photos.

Why RLS matters: Moltbook leaked about 1.5 million API keys because its public Supabase key shipped with RLS off. AI tools often skip it unless you ask.

Connect only the MCPs you need. Each one eats the agent’s context and can carry prompt-injection risk.

RUN (window 1): paste the prompt on the slide: Create a jobs table (photo_url, part, manual_page, note, user_id). Turn on RLS so users only see their own rows. Add a storage bucket for photos. Generate TypeScript types. When it finishes, type: show me the RLS policy you created. This is the database half of the “Save a job note” task. FALLBACK: open the Supabase dashboard and show the jobs table and its policy from rehearsal. —— The agent creates the table, the policy, the bucket and the types through the MCP, no dashboard clicking. Point it at a throwaway dev project, never production. Then ask it to show the RLS policy so the room sees it exists. Neon is a good alternative if you only need Postgres; Supabase also covers storage and login.
