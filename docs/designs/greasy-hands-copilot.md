## Problem Statement

A mechanic is holding a part with oily hands and needs to know what it is and how to work with it. Today that means wiping off, unlocking a phone, and scrubbing through a YouTube video or a PDF service manual. Build a phone web app where one photo of the part starts a hands-free, voice-guided job: identify the part, list tools and safety notes, then coach through each step, with "next / back / repeat / check" said out loud.

## What Makes This Cool

General AI cameras (Google Lens, ChatGPT camera, Gemini Live) *answer a question* about a photo. This app *runs the job*. It holds your place in a 9-step procedure, reads the torque spec aloud when you reach that step, and moves on when you say "next" with gloved hands. The stretch "Show Me" checkpoint lets the app *look at your work*: say "check," snap the caliper, hear "Not yet, the upper guide pin bolt is still in." That's the moment judges remember.

## Constraints

- **Time box: a few hours**, including deploy and rehearsal.
- **Audience: hackathon judges, live on stage.** The photo-to-coaching moment must work on the first try.
- One API key (Claude), and it never reaches the browser.
- Venue wifi is untrusted.

## Premises

1. The demo IS the product: one mobile web page (phone browser, no install). One photo → part identified → voice-guided step-by-step. Anything else is scope creep.
2. The difference from general AI cameras is "job mode": the model returns structured JSON (part, tools, ordered steps, torque specs, safety warnings), the UI holds your place, and voice drives it.
3. Voice uses the browser's built-in Web Speech API (`speechSynthesis` + `SpeechRecognition`). Recognition is flaky or absent on iOS Safari → demo on Android Chrome or a laptop, with giant tap buttons as fallback.
4. Model-generated specs can be wrong. Torque values are labeled "verify with service manual," and the pitch says so out loud.
5. Live-demo insurance: rehearse with the 2-3 real parts you'll bring, and keep a cached response for the hero part.
6. Distribution = a deployed URL plus a QR code on the slide.

## Approaches Considered

### Approach A: One Page + One Function
Static `index.html` + one `/api/identify` serverless function → Claude vision → structured job JSON; Web Speech voice; tap fallback. Effort S, risk Low. Chosen as the base (see below).

### Approach B: Conversational Copilot
Next.js plus mid-job voice questions with streamed answers. Rejected: streaming speech turn-taking doesn't fit a few-hour box and is where live demos break.

### Approach C: A + "Show Me" Checkpoints
A, plus a second `/api/check` call: a photo plus the current step goal → pass/fail verdict with a reason. Effort S+, risk Medium, easy to cut.

## Recommended Approach

**Approach C, built in strict order: A first, deployed, then the "check" stretch.**

### Architecture

```
phone browser (index.html + app.js, vanilla JS, HTTPS only)
  ├─ camera: getUserMedia rear preview (permission from first tap)      [O1]
  │    "snap"/"check" by voice or tap → grab frame to <canvas>
  │    fallback if getUserMedia denied: <input type=file capture> (tap only)
  ├─ ALWAYS downscale to ≤1024px JPEG q≈0.8 (~150-300 KB)               [R7]
  ├─ speak "Looking at your part" on upload                            [R8]
  ├─ POST /api/identify {image}   15s AbortController                  [R2]
  │    200 JobPlan | 413 too large | 429 | 502 bad_model_output | 504
  ├─ POST /api/check {image, step}  → {passed, reason} | {passed:null} (stretch)
  ├─ job id + step index in sessionStorage                             [O1]
  ├─ speechSynthesis: local voice (localService) reads step/spec/warning [O8]
  └─ voice state machine  listening | speaking | offline | idle        [R4,O3]
       parseCommand(whole utterance) → next|back|repeat|check|snap|retake
       onend → restart only if listening && job active (try/catch start)
       onerror network/not-allowed → offline: "Voice offline, use buttons" [R1]

Vercel functions (maxDuration 30)                                      [O4,O6]
  api/identify.js, api/check.js = thin (req,res) wrappers over pure cores
  handleIdentify({body, ip, callClaude}):
  ├─ rate limit 200 req / 10 min per IP (in-memory guard) → 429        [R3,O2]
  ├─ validate: image present, base64, ≤4 MB, mime jpeg/png/webp → 400/413 [R7]
  ├─ callClaude: raw fetch, forced tool call, 25s abort → 504          [O4]
  └─ validateJobPlan → 200 | 502 {error:"bad_model_output"} + log raw  [R5,O9]
  ANTHROPIC_API_KEY from env; workspace spend limit; rotate after event [R3]
```

**Models:** `claude-sonnet-5-5` for `/api/identify` (vision quality matters most). Use the same for `/api/check` first; try `claude-haiku-5-5` only if latency hurts on stage.

### JobPlan schema (the contract between model and UI)

```json
{
  "part": { "name": "Front brake caliper", "variant": "floating, single piston", "confidence": 0.92 },
  "job": "Replace front brake pads",
  "tools": ["14 mm socket + ratchet", "C-clamp", "bungee or wire hook", "torque wrench"],
  "safety": ["Car on jack stands, never just the jack"],
  "steps": [
    { "n": 4, "text": "Remove the two caliper guide pin bolts.",
      "spec": "25-35 Nm on reinstall", "warning": "Support the caliper; never let it hang by the brake hose",
      "check_goal": "Both guide pin bolts removed, caliper lifted off the bracket" }
  ],
  "unidentified": false
}
```

- `confidence` < ~0.6 or `unidentified: true` → the Identified screen says "Not sure. Retake closer, with the part number facing the camera."
- Every `spec` renders with "verify with service manual" underneath.
- `check_goal` exists so `/api/check` compares against a concrete, visual target, not the step prose.

### UI states (each one needs a design)

- **Capture:** idle / uploading (spinner + spoken "Looking at your part...") / error ("Couldn't identify your part. Tap to retry.", covers network, 15s timeout, 504, and 502 `bad_model_output` as "Something went wrong on our side. Tap to retry.") / 413 "Photo too large" / 429 "Too many requests, wait a minute" / camera denied (file-input fallback)
- **Identified:** confident / low confidence (retake prompt) / unidentified
- **Job mode:** listening / mic denied or unsupported (hide the mic hint, buttons only) / last step ("Job done" screen)
- **Check:** checking / pass ("Looks good," auto-advance) / fail (reason + Retry / Next anyway) / error (treat as "can't tell," allow Next)

### Demo insurance

- `cached/hero-part.json`: a known-good JobPlan for the hero part, generated by `scripts/eval-photos.mjs` through `handleIdentify` and passing `validateJobPlan` [O7]. Used **only** when `?demo=1` is set (your stage URL). Without the flag, failures show the retry screen and never the cached plan [R2].
- Rehearse the exact "check" shot (same part, same angle, same light) at least 3 times.

## Success Criteria

- On the demo device, photo of the hero part → named part plus first spoken step in under ~8 seconds, **measured** by `scripts/eval-photos.mjs` on the demo network [R8]; if median > 8s, shorten output, then try `claude-haiku-5-5`.
- Saying "next," "back," "repeat," "snap" and "check" works hands-free across a full job (camera via in-page preview), with tap buttons working when the mic is unavailable.
- With wifi off **and the page already open**, `?demo=1` runs the full hero job with tap buttons and spoken steps (local voice) [R1, O8]; recognition shows "Voice offline, use buttons".
- No judge ever sees another part's instructions: the cached plan loads only with `?demo=1` [R2].
- (Stretch) "check" on the rehearsed shot returns the right verdict 3 out of 3 rehearsal tries.
- Judges can scan the QR code and run it on their own phones.

## Distribution Plan

Web service on Vercel from the repo (git push → auto-deploy; preview deploys give HTTPS for mic testing, never LAN IPs [O11]). Set `ANTHROPIC_API_KEY` in the dashboard env vars, set a low workspace spend limit in the Anthropic Console, rotate the key after the event [R3]. Put the URL and a QR code on the pitch slide. No app store, no install. Tests run locally with `node --test` and `npx playwright test`; no CI for a hackathon (deferred).
